# Theming

A Shiny app's look comes from one full Bootstrap 5 CSS file. By default that file
is the bundled `shiny` preset. Passing a `theme` to a page function replaces it
with one of: a `ui.Theme` (compiled Sass), a CSS file or URL, or a "theme
provider" (Tagifiable / `HTMLDependency` objects, such as shinyswatch).

Key files:

| File | Role |
| --- | --- |
| `shiny/ui/_theme.py` | `Theme`, `SassCompileArgs`, `path_pkg_preset()`, `check_theme_pkg_installed()` |
| `shiny/ui/_theme_presets.py` | Generated preset lists (`ShinyThemePreset`, `shiny_theme_presets`, `shiny_theme_presets_bundled`, `shiny_theme_presets_bootswatch`) |
| `shiny/ui/_theme_brand.py` | `ThemeBrand(Theme)`, `BrandBootstrapConfig`, built by `Theme.from_brand()` |
| `shiny/www/py-shiny/brand/_brand-yml.scss` | py-shiny's own Sass layer file used for brand themes (not vendored) |
| `shiny/ui/_html_deps_external.py` | `shiny_page_theme_deps()`, `bootstrap_deps()`, `ThemeProvider` |
| `shiny/ui/_input_dark_mode.py` | `input_dark_mode()`, `update_dark_mode()` |
| `shiny/www/shared/sass/preset/<preset>/` | Vendored preset Sass layers (plus `bootstrap.min.css` for bundled presets) |

## The default Bootstrap CSS

`page_bootstrap()` is the base of every page function (`page_sidebar`,
`page_navbar`, `page_fillable`, `page_fluid`, `page_fixed`, and `page_auto` in
Express all forward `theme=` down to it). It puts
`shiny_page_theme_deps(theme)` at the top of `<body>`.

`shiny_page_theme_deps()`:

- Always adds `bootstrap_deps(include_css=theme is None)`: jQuery plus the
  `bootstrap` dependency (`shiny/www/shared/bootstrap/`, with the JS bundle and
  viewport meta tag). The CSS `bootstrap.min.css` is included only when no
  theme is given.
- Resolves `theme`: a `Theme` gives `theme._html_dependencies()`. A string
  starting with `http` or `//` gives a `<link>` in `head_content`. Any other
  `str`/`Path` goes through `check_path()` and then `include_css()`.
  Tagifiable, `HTMLDependency`, or `list[HTMLDependency]` pass through
  unchanged. Anything else raises `ValueError`.
- Re-adds `shiny_deps`, `components_dependencies` (bslib), ionrangeslider,
  datepicker and selectize **with `include_css=False`**. Their CSS is already
  compiled into every preset's Bootstrap CSS. These page-level copies take
  priority over the component-level copies (which do carry CSS), so standalone
  (non-page) contexts still get styles. The source comment says not to copy
  this pattern for new components; use CSS variables instead.

`shiny/www/shared/bootstrap/bootstrap.min.css` is generated by
`copy_shiny_preset_to_base_bootstrap()` in `scripts/_functions_sass.R`. It copies
the `shiny` preset's compiled CSS and rewrites its first-line Google Fonts
`@import url(...)` to `@import url("font.css")`, which uses locally vendored
fonts.

## `ui.Theme`

`Theme(preset="shiny", name=None, include_paths=None)` checks `preset` with
`check_is_valid_preset()` and collects user Sass in five lists. `to_sass()` puts
them together in this order:

```
_uses
@import preset/_01_functions.scss
_functions
_defaults
@import preset/_02_defaults.scss
@import preset/_03_mixins.scss
_mixins
@import preset/_04_rules.scss
_rules
```

- `add_uses()`, `add_functions()`, `add_mixins()` and `add_rules()` append.
  `add_defaults()` **prepends** (`self._defaults[:0] = ...`). Sass `!default`
  keeps the first value it sees, so the most recent `add_defaults()` call wins.
- Keyword arguments become `$kebab-name: value;` (`_` becomes `-`, `True`/`False`
  become `true`/`false`, `None` becomes `null`). `add_defaults` adds
  `!default`. It also rejects mixing positional and keyword arguments, because
  their relative order would be ambiguous.
- `add_sass_layer_file(path)` splits a file on `/*-- scss:{uses,functions,defaults,mixins,rules} --*/`
  markers (the Quarto/`sass_layer_file()` format). It drops the preamble before
  the first marker and joins repeated layers. It raises `ValueError` if there
  is no marker.
- Every `add_*` method and the `preset` setter call `_reset_css()`, which clears
  the cache and the tempdir.
- `Theme.available_presets()` returns `shiny_theme_presets`.
- `tagify()` raises `SyntaxError`. A `Theme` is valid only as a `theme=` argument.

### Compilation and caching

- `to_css(compile_args=None)` returns the cached `_css` if it is set. Otherwise,
  when `_can_use_precompiled()` is true (preset is in
  `shiny_theme_presets_bundled` = `bootstrap` and `shiny`, and there are no
  customizations), it reads the vendored `bootstrap.min.css`. In every other
  case it compiles `to_sass()` with libsass (`sass.compile`), using
  `output_style="compressed"` and the constructor's `include_paths`. Passing
  `include_paths` inside `compile_args` raises `ValueError`.
- libsass (`sass` module) and `brand_yml` are optional. The `shiny[theme]` extra
  in `pyproject.toml` provides them. `check_theme_pkg_installed()` raises an
  `ImportError` that names the pip command to run.
- `_html_dependencies()` returns one `HTMLDependency`. For precompiled themes it
  points at the preset directory. For anything else it writes `to_css()` once to
  `<tempdir>/bootstrap.min.css` and points there. Tempdirs are also stored in the
  module-level `theme_temporary_directories` set. This stops them from being
  garbage-collected (and deleted) after the throwaway `Theme` object is
  collected, which would happen before the files are served.
- The dependency name is `shiny-theme-<name or preset>`, cleaned by
  `make_valid_path_str()`. Its stylesheet carries a `data-shiny-theme` attribute.
- Extension points for third-party providers (for example shinyswatch):
  `_dep_name()`, `_dep_css_name()`, `_dep_css_precompiled_path()`, and
  `_html_dependencies()`, which returns a list so subclasses can add
  dependencies. See `shiny/api-examples/theme/app-core-shinyswatch.py`.

## Presets

- `_theme_presets.py` is **generated** by `write_python_preset_choices()`
  (`scripts/_functions_sass.R`), which `scripts/htmlDependencies.R` calls
  (`make upgrade-html-deps`). Do not edit it by hand. Presets are `bootstrap`,
  `shiny`, and `bslib::bootswatch_themes()`. `BUNDLED_PRESETS <- c("bootstrap", "shiny")`
  lives at the top of `htmlDependencies.R`.
- For each preset the script builds the full bslib theme (shiny Sass, bslib
  components, layer markers) and splits it into `_01_functions.scss` through
  `_04_rules.scss` under `shiny/www/shared/sass/preset/<preset>/`. The shared
  Sass sources are copied alongside.
- `compile_theme_sass()` compiles every preset as a smoke test, but **keeps
  `bootstrap.min.css` only for bundled presets**. Bootswatch themes always
  compile at runtime and need libsass.
- Vendoring workflow and pitfalls: see [assets.md](assets.md).

## brand.yml (`Theme.from_brand`)

`Theme.from_brand(brand)` accepts a `brand_yml.Brand`, or a path (`__file__`, a
directory, or a `_brand.yml` file) that it loads with `Brand.from_yaml()`. It
returns `ThemeBrand`. The import of `ThemeBrand` is deferred inside the method
to avoid a circular import, because `_theme_brand.py` subclasses `Theme`.

`ThemeBrand.__init__`:

1. Builds a `BrandBootstrapConfig.from_brand()` from `brand.defaults.bootstrap`
   and `brand.defaults.shiny.theme`. For preset, version, and individual
   defaults, `shiny.theme` wins. functions, mixins and rules are concatenated
   with bootstrap first. A Bootstrap major version other than the bundled one
   gives a warning and falls back to the bundled version.
2. Names the theme `meta.name.short`, then `meta.name.full`, then `"brand"`.
3. Adds `_brand-yml.scss` with `add_sass_layer_file()`.
4. Adds defaults through `_add_defaults_hdr()`. Because `add_defaults`
   prepends, the final precedence is `color.palette` > brand-supplied Bootstrap
   defaults > `color` > `typography`. Theme colors become
   `$brand_color_<name>`. Palette entries become `$brand-<name>` plus
   `--brand-<name>` on `:root` (as a rule). Palette names that match a
   Bootstrap color (`bootstrap_colors`) also set `$red`, `$blue`, and so on.
   Typography becomes `$brand_typography_<field>_<prop>` (base size in `rem`).
5. `_html_dependencies()` puts a fonts dependency first
   (`brand.typography.fonts_html_dependency()`), written to `<theme tempdir>/fonts`.

## Dark mode

- `input_dark_mode(id=None, mode=None)` renders the bslib web component
  `bslib-input-dark-mode` through `web_component()` (which attaches
  `components_dependencies()`), with `attribute="data-bs-theme"`. The JS (in
  `shiny/www/shared/bslib/components/web-components.min.js`) sets that attribute
  on `<html>`, which switches Bootstrap 5.3 color modes. `mode=None` follows the
  OS preference. The initial value passes through `restore_input()` for
  bookmarking.
- `update_dark_mode(mode)` sends the custom message `bslib.toggle-dark-mode`
  with `method: "toggle"`.
- Playwright controller: `InputDarkMode` in `shiny/playwright/controller/_input_buttons.py`.
- Navbar light/dark (`navbar_options(theme=...)` in `shiny/ui/_navs.py`) is a
  separate `data-bs-theme` setting on the navbar only.

## Pitfalls

- **`add_uses()` alone does not trigger compilation.** `_has_customizations()`
  checks functions, defaults, mixins and rules but not `_uses`. As a result,
  `Theme("shiny").add_uses(...)` serves the precompiled CSS and ignores the uses.
- **`Theme("shiny")` is not identical to `theme=None`.** The preset's
  precompiled CSS `@import`s Google Fonts remotely. The default
  `shiny/www/shared/bootstrap/bootstrap.min.css` uses the local `font.css`.
- **`add_defaults` order is reversed** compared with the other `add_*` methods
  (see above). Keep this in mind when reordering calls in `ThemeBrand`.
- **Tempdirs are never freed** while the process runs, except through
  `_reset_css()`. Every customized `Theme` used in a page leaves one in
  `theme_temporary_directories`.
- **Stale comments on `all_files`:** `_dep_create()` sets `all_files=False`
  (its comment says "Branded themes re-use this tempdir"), while
  `ThemeBrand._html_dependencies()` says it relies on `all_files=True`. Fonts
  still work only because they ship as their own dependency.
- **A preset added upstream needs the R script.** Only
  `make upgrade-html-deps` updates `_theme_presets.py`, the Sass layers, and
  the bundled CSS together.
- **Docs example name:** `Theme` uses `@add_example(example_name="theme")`
  because `shiny/api-examples/theme/` is lowercase. Without the explicit name,
  Linux docs builds fail to find it.
- **Theme CSS replaces, not augments.** To tweak styles without replacing
  Bootstrap, use `ui.include_css()`, not `theme=`.
